# 语种专属规则

> 适用范围：本仓库界面文案（8 语种）。以下规则与 `apps/api/services/i18n.py` 的发布门禁、`apps/shared/src/styles/tokens.css` 的字体栈、`apps/shared/src/i18n/format.ts` 的数字格式保持一致。规则冲突时以代码为准，并回头修本文件。
>
> 长度基准数据来自 `i18n_seed.json` 实测（1429 key，取源文 ≥4 字与 2–8 字短标签两组），不是经验值。

## 0. 长度基准（决定「超长」是否真的超长）

以 **字符数 / zh-CN 字符数** 计。服务端发布门禁固定用 `> 1.8×` 告警，但那只适合当作「异常兜底」——实测拉丁语系与泰/阿/越语种**中位数就在 2.7–3.8 倍**，按 1.8 倍判会把 80% 以上的正常译文标红（项目已知现象，见技术方案 §17.1）。

本技能用「比例上限 + 短标签绝对豁免」双判据：`len(译文) > max(比例上限 × len(源文), 短标签豁免)` 才报 `TOO_LONG`。加豁免是因为纯比例判据会把「取消 → Cancelar」（2 字 → 8 字，4 倍）这种完全正常的短标签判超长。

| 语种 | 中位数（全量） | 比例上限（≈p95） | 短标签豁免（p95 字数） | 说明 |
|---|---|---|---|---|
| zh-Hant | 1.00 | 1.3× | 6 字 | 术语替换型，长度几乎不变 |
| ja | 1.29 | 2.4× | 11 字 | 假名+汉字混排，比中文略长 |
| ar | 2.71 | 4.4× | 21 字 | 连写短、但词形长 |
| th | 2.75 | 4.4× | 21 字 | 无词间空格，长度全在字素上 |
| en | 2.80 | 4.4× | 21 字 | |
| vi | 3.00 | 4.7× | 23 字 | 声调符号额外占位 |
| es | 3.40 | 5.6× | 26 字 | 最长，按钮/表头必须允许换行 |

两条使用原则：

1. **比例上限只用来发现「离谱的扩张」**（约 5% 尾部），不代表一定会溢出——真正的布局判断要传控件硬上限：`--max-len ar=40 --max-len es=32`。
2. 超长优先缩短（换短词、去量词、拆句），不硬截断、不用省略号糊弄；按钮固定宽 96px、侧栏 132px 这类硬边界以实测截图为准。

## 1. 阿拉伯语（ar）

### 1.1 双向文本：默认不要手插隐形字符

**本项目口径：词条值里不写 U+2068（FSI）/ U+2069（PDI）**。原因有三：

1. 词条值最终进入 DOM 文本节点，隔离应由渲染层负责（`dir` / `unicode-bidi` / `<bdi>`），文本里塞隐形字符会让运营在后台搜不到、改不动，也会污染长度统计；
2. 现网 1429 个 key 的 ar 值中 FSI 出现次数为 **0**，全部靠 CSS 处理，已实测 8 语种截图 `dir/lang` 正确；
3. 同一份词条还会被导出成 xlsx/CSV 给译员与客户，隐形字符在表格里是无形的坑。

具体做法分三层：

| 场景 | 做法 |
|---|---|
| 普通 RTL 文案（含 `{{name}}`） | 不处理。占位符替换后的值在同一段落内，方向由容器决定 |
| 单号 / 金额 / 代码 / 型号（`OOLU8882850350`、`3X2DDA7376771`） | 这些值**不翻译**，且必须由外层容器强制 `direction: ltr; unicode-bidi: isolate`（现网 `.mono` 已加） |
| 纯文本通道（CSV 导出、邮件、短信、第三方系统对接） | 无处挂 CSS，此时才允许在值内加 `\u2068…\u2069`，并在 `remark` 注明「含 BiDi 隔离符」 |

> 判断口诀：**能挂样式就不写字符**。只有落到纯文本时才用 FSI/PDI。

### 1.2 数字

- 一律使用**西方数字** `0-9`，禁止阿拉伯-印度数字 `٠١٢٣`（`format.ts` 已固定，勿传 `numberingSystem: 'arab'`）。理由：单证原件（提单/报关单）上的数量、金额、HS 编码都用西方数字，界面显示两套数字会让操作员对不上原件。
- 占位符插值进来的数字同样走西方数字，不要手动转。

### 1.3 括号与标点

- 阿拉伯语环境下括号会按 RTL 自动镜像，**不要手动把 `( )` 写成 `) (`**，也不要为了"看起来对"加 LRM/RLM 标记。
- 问号用 `؟`，逗号用 `،`，不要混用拉丁标点。
- 省略号用 `…`，不用三个句点。

### 1.4 方向性图标

含「前进 / 后退 / 下一步 / 展开」语义的图标（chevron、arrow、back、分页箭头）在 RTL 下必须水平翻转，走 `[dir=rtl] [data-icon=…] { transform: scaleX(-1) }`（现网 `responsive.css` 已实现）。**业务图标、状态图标、预览高亮层不翻转**（高亮层是物理坐标，翻转即错位）。

### 1.5 词形

- 阿拉伯语形容词后置、名词在前：`قائمة المستندات`（单证列表）而不是 `المستندات قائمة`。
- 界面标签用名词短语（`حفظ`、`حذف`），不要用带人称代词的长句。
- 本期**不做 CLDR 复数六态**（项目决策 D2）。遇到数量必须靠文案改写：`3 ملفات` 这种形态有歧义，改成 `عدد الملفات: 3`（文件数：3）。

## 2. 繁体中文（zh-Hant）

1. **是术语替换，不是字形映射**。必须过 `terminology.md` §7 的实测对照表：保存→儲存、字段→欄位、文件→檔案、导出→匯出、设置→設定、信息→資訊、默认→預設、刷新→重新整理、审计→稽核。
2. **禁止 OpenCC 自动转换**（项目决策 R-18）：自动转换只会得到「繁体字形 + 大陆用词」的混合体，这是明确的失败态。
3. locale code 固定 `zh-Hant`，不要写 `zh-TW`（`tokens.css` 的 `:lang(zh-Hant)` 字体栈与之对齐）；后端匹配层已把 `zh-TW/HK/MO` 映射到 `zh-Hant`。
4. 与 `zh-CN` 同形率 > 95% 会被发布门禁告警（疑似直接贴了简体）。同形率高不等于错——"合计/合計"这种只换字形的词本来就同形，但要能解释。
5. 港台标点：`「」` 优先于 `“”`（现网混用，新词条统一 `「」`）。
6. 数字与英文缩写保持半角。

## 3. 简体中文（zh-CN）

1. 源语言。`t('key', '源文')` 的第二参是**唯一源文**，必须与代码字面量一字不差；改文案要同时改代码与词表。
2. 不写繁体字、不写全角英文（`ＡＢＣ`）、不用 `……` 与 `。。。` 混排。
3. **新增汉字会撞字体门禁**：代码里出现的汉字必须在 `apps/shared/src/assets/fonts/misans/subset-chars.json` 内（现 737 字，含词表全部 zh-CN 用字）。新增字只能走 `FONT-NOTICE.md` 的子集重建，不能靠换同义词绕过（会牺牲文案质量）。
4. 数值与单位间不加空格（`3.5 kg` 除外，按单证原文）；数量词用「个」而非「只」。

## 4. 英语（en）

1. 长度基准与缩写宿主。Incoterms、HS、UN/LOCODE、船公司代码原样保留，不扩写（`CIF` 不写 `Cost, Insurance and Freight`）。
2. UI 用 sentence case（`Save changes`），不用 Title Case；表头可用 `Container No.` 这类带点的缩写。
3. 动作用祈使式（`Save` / `Delete` / `Retry`），状态用过去分词或名词（`Voided` / `To confirm`）。
4. 不用 `Please` 开头（界面文案冗余），确认弹窗例外。

## 5. 日语（ja）

1. 按钮与菜单用惯用 UI 语：`保存`、`送信`、`戻る`、`検索`、`削除`、`キャンセル`、`再試行`。**不要**写「保存する」「検索を行う」这类动词短语。
2. **不得混入简体中文词**。这是本项目真实事故：日文差异页曾出现「阻断」（应为 `ブロック`），共 5 处。同一批次的 `単証/報関/装箱` 这类简体写法同样禁止。
3. 全角/半角统一：正文与标点用全角，数字、占位符、缩写用半角；括号用 `（）`。
4. 同一界面不得混用敬体（です・ます）与常体（だ・である）。界面标签统一**体言止め**（名词结句），提示句用敬体。
5. 单证术语用日本海运实务写法：`船荷証券`（B/L）、`荷受人`（Consignee）、`荷送人`（Shipper）、`積出港`、`揚陸港`、`容積`、`通関申告書`。
6. 假名字体回退系统字体（MiSans 无假名），观感与中文不同属已知限制；验收只看不丢字、不裁切。

## 6. 泰语（th）

1. **无词间空格**：不要按空格切分、不要为对齐插空格、不要断行。换行交给渲染引擎。
2. 元音与声调符号上下堆叠，行高不足会裁切：`tokens.css` 已给 `:lang(th)` 设 `line-height: 1.65`，且 `letter-spacing: 0`（任何字距都会破坏泰文词形）。
3. 按钮文案动词优先、能省则省：`บันทึก`（保存）、`ลบ`（删除）、`ยกเลิก`（取消）。状态位用完成态：`ยกเลิกแล้ว`（已取消）。
4. 单证名带量词：`ใบตราส่ง`（提单）、`ใบขนสินค้า`（报关单）、`ใบรายการบรรจุหีบห่อ`（装箱单）。
5. 不要用拉丁字母音译行业词（`คอนเทนเนอร์` 是通用借词，可用；随机音译不行）。

## 7. 西班牙语（es）

1. **锁定变体**：本项目按中性/拉美口径出稿（用户主要在拉美与西语区货代），锁定后全表一致。禁止 `ordenador` / `computadora` 混用；统一用 `contenedor`（集装箱）、`archivo`（文件）、`guardar`（保存）、`eliminar`（删除）。
2. 长度最长（中位 3.4×），按钮与表头必须允许换行，禁止 `white-space: nowrap` + 固定宽。
3. 名词性数一致：`Tipo y número de contenedores`——形容词/名词复数必须对齐，机翻常在这里出错。
4. 行业固定词：`Cargador`（Shipper）、`Consignatario`（Consignee）、`Parte a notificar`（Notify party）、`Conocimiento de embarque`（B/L）、`Declaración aduanera`（报关单）、`Peso bruto`、`Volumen`。
5. 界面动作用不定式（`Guardar` / `Cancelar`），不用命令式（`Guarda`）。

## 8. 越南语（vi）

1. **声调符号必须完整保留**：禁止降级为无调 ASCII（`Don hang` ✗ / `Đơn hàng` ✓）。Inter 的 `latin-ext` + `vietnamese` 子集已覆盖，验收必须抽查 `ặ ệ ỡ ữ ẩ ỹ` 六个字不丢形。
2. 长度偏长（中位 3.0×，短标签 3.5×），按钮优先短词。
3. 行业词：`Vận đơn`（B/L）、`Người gửi hàng` / `Người nhận hàng`、`Bên thông báo`、`Tờ khai hải quan`、`Bảng kê đóng gói`、`Trọng lượng cả bì` / `Trọng lượng tịnh`。
4. 音节间必须有空格（与泰语相反），不要照搬泰语的无空格习惯。
5. Đ/đ 与 D/d 是两个字母，代码里比对时注意 Unicode 归一化（`đ` = U+0111）。

## 9. 跨语种通用

- 占位符 `{{name}}` 前后不要加语种特有标点（西语 `¿`、阿语 `،`）去"修补"语序，改文案本身。
- 术语一致性优先于语句流畅：同一概念在 8 个语种里各只有一个译法。
- 译文里不出现 HTML 标签（项目硬规则），需要强调时改文案或由组件控制。
- 本次未支持：印尼语、德语、法语、韩语。新增语种只需在 `i18n_locales` 加一行、在本文加一节、在 `qa-rules.md` R7 补一句，主流程不动。
